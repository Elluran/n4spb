## How a landmark module works
* `export const OWNS_GROUPS = true;` (static export at the top of `<module>.js`) + the sub-groups in `<module>/groups.js` (`GROUPS_LIST = [{ key, name, nameEn, ids: ['w123', 'r456', ...] building ids (parts of an id are claimed automatically), osm: ['w789'] non-building ids (paving, monuments, fences, bridge decks you draw yourself), at: [x, z], note }]`). The generic modules (city / environment / streets) then skip the claimed objects. Find ids with `L.buildingById`, by position (`L.buildingAt(x,z)`), or in the dossier. Until you flip OWNS_GROUPS the generic blockout is drawn. A claim of an object you do NOT draw makes a hole in the city: draw everything you claim.
* Build functions follow `docs/DESIGN.md` section 1-2 (ctx API: materials only from `ctx.mat`, `ctx.addStatic`, colliders `ctx.physics`, walk boxes for decks / steps, `ctx.rng`, zones for interiors). Everything repeated more than ~40 times is an InstancedMesh. Static meshes are merged by the engine (batching + outline proxies); do not use `noBatch` without a reason, do not use layers 2-4.
* Publish what others need as `ctx.services.<yourModule>` (e.g. monuments / photo spots appended to `ctx.services.landmarks`, entrances, fences). Read services of earlier modules with optional chaining. Collisions: thin wall boxes; anything that places the player / an NPC must test `L.insideBuilding` and `L.isOnRoad`; the roof map makes everything inside a footprint walkable (a sign on a roof is an obstacle, a canopy a floor). Colliders / walk boxes for steps, bridges, plinths so the player can walk up to and around the sight; the player can also fly (check roofs landing).
* Module load order is in `src/main.js` MODULES (environment, streets, city, rail, landmarksA..D, E, F, G, H, bridges, metro, props, traffic, people, wildlife, drive). A broken module must not break the others (write defensively; one `try/catch` per sub-part like landmarksD).
* Header comment in each file: what it draws, which dossier / photos it is based on, parameters worth knowing.

## Resource etiquette
The machine runs several agents; the usage limit is shared and was hit twice: no more than ~5 heavy agents run at once, so stay economical: do not re-read huge files repeatedly, ask few cameras per screenshot run, stop when the result is good (typically 8-12 screenshot rounds; the priority sights deserve more).
